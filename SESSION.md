# Почему сессия слетает «с тела» и с парсера

Telegram **убивает auth-ключ целиком**, если одна и та же Telethon-сессия
подключается с **двух процессов сразу** (`AuthKeyDuplicatedError`).

После этого сессия пропадает:

1. у парсера (не авторизован),
2. в списке устройств на телефоне («Активные сессии» / «с тела»).

Это не «потеря файла» — ключ отозван на стороне Telegram. Нужен **новый логин**.

## Что делать прямо сейчас

1. Останови **все** копии парсера: docker / pm2 / screen / второй сервер / replicas.
2. Запусти **ровно один** процесс.
3. `/admin` → **Авторизация TG** (номер + код + 2FA).
4. Проверь `/admin` → **Статус сессии TG** — должно быть «Жива: да».
5. Убедись, что после деплоя не стираются:
   - `telethon_auth.string` (в корне проекта),
   - или env `TELETHON_SESSION` / `TG_SESSION`.

## Чего нельзя делать

- `replicas > 1` / два контейнера с одной сессией
- один и тот же `TELETHON_SESSION` на двух машинах
- старый `log_out()` (в коде больше не вызывается — он тоже убивает ключ)
- «Завершить все другие сессии» в Telegram, если там висит парсер

## Флуд PriceNFT / маркет тоже валит сессию

Если долбить `@PriceNFTbot` (CD 3с) и маркет (20+ параллелей), Telegram даёт
длинный `FloodWait`, а при игноре — может отозвать ключ / забанить акк.

В коде теперь:
- **пауза перед КАЖДЫМ запросом** к Telegram (`TG_REQUEST_GAP`, по умолчанию 2с)
- запросы идут строго по одному (общий lock)
- авто-сбор PriceNFT **выключен** (`AUTO_PRICENFT=0`)
- фон маркета медленный (parallel 3–4, пауза 60с)
- при любом FloodWait — глобальный API cooldown, фон встаёт
- PriceNFT вручную из `/admin`, CD = 12с

Env:
- `TG_REQUEST_GAP=2.5` — длиннее пауза между запросами
- `AUTO_PRICENFT=1` — авто PriceNFT (не рекомендуется)
- `AUTO_DB_KEEPER=0` — выключить фон БД

## БД не пропадает при смене акка

Бэкап лежит вне `data/`:
- `neptun_gifts_backup.db` (корень)
- `backups/gifts_*.db` (ротация)

`/admin` → **💾 Скачать БД** — бот пришлёт файл в чат.  
Если сессия слетела / новый акк — **пришли этот .db файл боту** или жми **📥 Восстановить БД**.  
При старте, если живая БД пустая — бэкап поднимается сам.

## Как бот защищается

- `parser.lock` + `fcntl` — второй процесс сразу выходит
- StringSession бэкап в `telethon_auth.string` + `data/session/auth.string`
- keepalive + persist
- logout только локальный disconnect, без `log_out()`
- антифлуд cooldown при FloodWait
